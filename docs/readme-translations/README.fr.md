**Écrivez votre prochain article avec moins de tâches répétitives dans un espace de travail scientifique moderne.**

Oleafly est une application gratuite et open source pour la rédaction scientifique. Utilisez-la pour des articles, thèses, rapports, présentations, livres, CV et autres documents techniques. Travaillez en LaTeX, Typst ou Markdown. La source, le PDF, les citations, les figures, les vérifications, l'historique Git et les outils IA facultatifs restent dans le même projet.

## Pourquoi Oleafly

La plupart des workflows de rédaction scientifique forment une chaîne d'outils séparés : un éditeur, un compilateur, un lecteur PDF, un gestionnaire de bibliographie, un outil de diagrammes, Git, une liste de vérification et, parfois, un chat IA qui ne voit pas le projet. Le travail se disperse entre plusieurs fenêtres au moment même où l'argumentation se complexifie.

Oleafly réunit ces outils autour d'un même projet. La source reste du texte brut. Le PDF est à côté. Vous pouvez trouver une citation depuis la phrase que vous écrivez, conserver une figure en TikZ et examiner les modifications de l'assistant avant qu'elles n'atteignent le projet.

### Trois façons de travailler

| Workflow | Ce que cela vous apporte | Ce qu'il vous reste à résoudre |
| --- | --- | --- |
| Éditeur cloud hébergé | Mise en route rapide, accès dans le navigateur et service géré | Faire confiance à une couche de données hébergée et adapter votre workflow à ses limites |
| Stack locale à construire soi-même | Contrôle des fichiers, des outils et de l'infrastructure | Choisir, installer, configurer et maintenir chaque élément |
| Oleafly | Un espace de travail de bureau local réunissant l'éditeur, les moteurs, le PDF, les citations, les figures, les vérifications, Git et les agents facultatifs | La coédition en direct et la synchronisation en arrière-plan entre appareils ne sont pas disponibles dans cette version |

Oleafly vous offre un espace de travail guidé, sans enfermer votre manuscrit dans un format propriétaire ni dans un service permanent.

## Ce qui reste sur votre ordinateur

Le travail essentiel reste sur votre ordinateur : fichiers du projet, indexation, compilation avec un moteur local disponible, aperçu PDF, vérification orthographique, vérification grammaticale, Preflight, historique Git, points de restauration et terminal. Aucun compte n'est nécessaire pour ces tâches.

L'application ne se connecte au réseau que pour les actions qui en ont besoin : recherche bibliographique, métadonnées DOI, opérations GitHub, IA hébergée, Zotero, serveurs MCP que vous connectez, recherche de paquets sur Typst Universe et CTAN, et téléchargement facultatif de moteurs, de paquets et de modèles. Les versions publiées vérifient aussi la présence d'une mise à jour à chaque démarrage de l'application. Les modèles Ollama locaux gardent le trafic du modèle sur votre ordinateur. Quand l'un de ces services est indisponible, l'application affiche un état hors ligne ou indisponible.

| Reste local par défaut | N'a lieu que si vous le choisissez |
| --- | --- |
| Source et métadonnées du projet | Recherche bibliographique et de citations |
| État de l'éditeur et index du projet | Connexion GitHub, push, pull et publication |
| Compilation LaTeX avec le moteur inclus lorsque les paquets sont disponibles | Fournisseurs IA hébergés |
| Compilation Typst lorsque les paquets sont en cache ou conservés dans le projet | Téléchargements facultatifs de moteurs, de paquets et de modèles |
| Rendu PDF et inspection du texte | Téléchargements de skills depuis la bibliothèque de domaines |
| Vérification orthographique, vérification grammaticale et Preflight | Clients MCP externes sur localhost |
| Historique Git et points de restauration automatiques | Zotero, alphaXiv et les autres serveurs MCP que vous connectez |

## Commencez avec un vrai projet

### Des modèles que vous pouvez modifier

Commencez par un article, un article de revue, une thèse, une revue de littérature, un rapport, un livre, une présentation Beamer, un poster, un devoir, une lettre, une bibliographie, un CV ou un diagramme. Les modèles sont des projets source ordinaires avec un moteur déclaré, un document principal, un type de document, des ressources et des métadonnées d'aperçu. Avant de créer le projet, vous pouvez voir un aperçu rendu et le moteur qu'il utilise.

La galerie filtre par moteur, catégorie, compatibilité hors ligne et adéquation ATS. Les modèles inclus fonctionnent sans compte de modèles. Les packs de modèles, polices et ressources facultatifs ne sont téléchargés qu'après votre sélection.

### Apportez votre travail existant

Importez un ZIP de projet ou un dépôt GitHub, convertissez un DOCX avec Pandoc ou utilisez un PDF comme point de départ pour créer du LaTeX modifiable. Les importations deviennent des fichiers de projet locaux ; la source d'origine reste donc intacte pendant que vous examinez le résultat.

Pour un PDF doté d'une couche de texte, la reconstruction est déterministe. Elle extrait le texte, la mise en page, les équations et les figures qu'elle peut identifier, signale ses limites et vous laisse un LaTeX modifiable plutôt qu'un document opaque. Un PDF numérisé peut être transcrit par un modèle de vision exécuté en local. Si vous connectez un fournisseur capable de vision, il peut ensuite aider à affiner le projet importé.

### Chaque projet est un dossier accessible sur votre disque

La bibliothèque Oleafly suit l'identité du projet, son moteur, le type de document, les signets, l'état de l'aperçu et l'historique. Le manuscrit reste un répertoire normal. Vous pouvez ouvrir la source dans un autre éditeur, l'inspecter dans un terminal, la partager avec un coauteur ou la versionner avec Git. Oleafly n'a pas besoin d'une base de données de documents propriétaire pour compiler votre travail.

L'application garde ses artefacts de compilation et ses métadonnées locales séparés de la source. Un projet peut conserver ses choix de moteur et de document principal dans `project.json`, afin qu'un clone ou une archive de sources exportée s'ouvre avec les mêmes réglages de projet.

## Rédigez l'article en gardant sa structure

### Un éditeur source pour les documents structurés

L'éditeur CodeMirror s'appuie sur un index couvrant tout le projet. Cet index recense les titres, labels, clés de citation, macros, environnements, fichiers inclus et diagnostics de compilation du manuscrit.

En LaTeX, Typst, Markdown et BibTeX, vous disposez de :

- Mise en évidence syntaxique adaptée au moteur pour les commandes, environnements, mathématiques, commentaires, balises et entrées bibliographiques.
- Complétion des labels, clés de citation et chemins de fichiers du projet. Les fichiers LaTeX complètent aussi les commandes et environnements, et les fichiers Typst complètent les fonctions, les paquets et les styles bibliographiques.
- Diagnostics en direct pour la syntaxe, les erreurs de compilation, les citations indéfinies, les clés en double, les labels en double et les références rompues.
- Plan local et global du document avec symboles, labels, citations, macros et relations entre fichiers.
- Recherche et remplacement, pliage du code, onglets multi-fichiers, mode Vim, comptage des mots, insertion de commandes slash et raccourcis clavier configurables.
- Assistants structurels LaTeX pour `\item`, `\begin` / `\end`, les environnements, les délimiteurs mathématiques, les légendes et les schémas d'insertion courants.
- Assistants Typst : paires de `$` pour les mathématiques, les listes se poursuivent avec Entrée et `/` ouvre les extraits.
- Infobulles pour les numéros et pages de labels compilés, les aperçus d'équations et les miniatures des images ciblées par `\includegraphics`.

### Insérez des blocs LaTeX, de la mise en forme et des symboles

L'éditeur LaTeX garde les structures courantes à portée d'un clic tout en vous laissant la main sur la source. Passez de la vue Code à la vue Visual, annulez ou rétablissez une action, choisissez un niveau de titre, mettez le texte en forme, insérez des références et construisez un tableau ou une figure sans mémoriser chaque commande. Les fichiers Typst disposent des mêmes outils dans leur propre barre d'outils, qui écrit du balisage Typst.

### Vue source et vue visuelle

La vue source est la représentation de référence. Lorsque le moteur le permet, activez l'éditeur visuel pour LaTeX, Typst ou Markdown et modifiez la prose, les équations, les citations, les tableaux et les figures sur une surface orientée page. Les mathématiques, notes de bas de page, théorèmes, figures, tableaux et couleurs s'affichent comme des nœuds natifs modifiables ; le texte enrichi et les images collés deviennent le balisage propre au document, et une barre d'outils flottante modifie les tableaux sur place. La source reste disponible pour Git, les éditeurs externes et les modifications manuelles.

Utilisez la vue visuelle pour les retouches à l'échelle de la page. Revenez à la source lorsque vous avez besoin d'un contrôle précis des commandes, paquets, environnements ou de la mise en page.

### Relisez votre prose en local

Hunspell gère l'orthographe avec le pack de dictionnaire sélectionné et vos ajouts personnels ou propres au projet. Harper vérifie la grammaire et le style au moyen d'un masque de prose tenant compte du document ; les commandes, commentaires, corps mathématiques et arguments machine ne sont donc pas traités comme de la prose ordinaire.

Le profil académique évite les règles qui gênent l'écriture scientifique et chaque résultat propose une action locale : le remplacer, l'ignorer (pour l'instant, dans ce projet ou partout) ou désactiver la règle. Les règles que vous avez désactivées apparaissent dans Paramètres, pour que vous puissiez les réactiver. La relecture s'exécute en local et ne nécessite aucun fournisseur IA.

### Recherchez dans tout le projet

Recherchez dans tout le projet depuis le panneau Recherche. L'index du projet relie fichiers source, titres, labels, citations, macros et fichiers inclus ; une thèse composée de nombreux fichiers est ainsi plus facile à parcourir qu'une série d'onglets d'éditeur.

## Compilez avec LaTeX, Typst ou Markdown

Oleafly garde la compilation près du manuscrit et transforme la sortie du compilateur en diagnostics liés à la source. Le moteur est choisi par projet ; l'éditeur, l'aperçu, SyncTeX, Preflight et les commandes d'export suivent les capacités réelles du moteur.

| Moteur | Utilisation principale | Détails importants |
| --- | --- | --- |
| LaTeX avec Tectonic | Compilations LaTeX portables avec moteur inclus | Inclus dans l'application de bureau ; prend en charge les projets multi-fichiers, les images, les citations, Biber (sauf sur Linux ARM64), SyncTeX, la compilation isolée de figures et les compilations hors ligne mises en cache lorsque les paquets sont disponibles |

## Littérature et citations

### Recherchez depuis la phrase que vous écrivez

Citation Search interroge arXiv, Semantic Scholar, Crossref, PubMed et OpenAlex au même endroit, ainsi que Google Scholar lorsque vous ajoutez une clé Serper. Il regroupe les résultats en double, garde les métadonnées visibles et vous permet d'enregistrer une référence dans la bibliothèque de littérature locale.

Vous pouvez aussi rechercher une citation par DOI, ID arXiv, URL ou titre. Importez une bibliothèque existante depuis Zotero RDF, EndNote XML, RIS ou BibTeX, ou connectez Zotero dans Paramètres > Intégrations et importez toute votre bibliothèque depuis le panneau Références. L'index du projet fournit la complétion des clés de citation, la navigation entre références, des détails au survol et des diagnostics pour les citations indéfinies, les clés en double et les métadonnées bibliographiques incomplètes.

### Recherchez les références manquantes dans le document

Depuis le mode document, Oleafly découpe la sélection ou le manuscrit en paragraphes de prose, interroge les sources de littérature configurées, retire les articles déjà présents dans la bibliographie et classe le reste sur une échelle de 0 à 100. Un fournisseur IA peut ajouter un bref raisonnement POUR / CONTRE. Lorsque l'IA est désactivée, l'analyse utilise un classement heuristique local.

Enregistrez les résultats dans la bibliothèque de citations locale, copiez le BibTeX ou ajoutez une entrée sélectionnée à la bibliographie du projet et insérez sa citation.

### Relisez un article avec deux voix

Le mode de relecture peut utiliser un fournisseur IA configuré pour lire le document actuel ou une sélection capturée selon deux styles :

- Amical : les points forts d'abord, puis des suggestions précises et constructives.
- Feu : un test de résistance façon Reviewer #2, centré sur les affirmations, les méthodes et les preuves.

La relecture est une action facultative de l'assistant. Elle ne remplace ni les consignes de la revue ni un coauteur humain.

### Gardez les dossiers de recherche à côté du manuscrit

Liez un jeu de données, une bibliothèque de sources, un dossier d'analyse ou un autre répertoire de recherche sans le déplacer dans le projet. Oleafly lit les dossiers liés et n'y écrit jamais. Ils restent exclus de la compilation, de la recherche du projet et de Git ; si un chemin est indisponible, l'interface indique clairement qu'il manque ou qu'il est illisible.

### Recherchez des laboratoires et des échéances

La galerie d'outils comprend Lab Search pour les institutions de recherche répertoriées par OpenAlex, avec des filtres par pays et des liens vers les fiches institutionnelles, ROR et OpenAlex. Conference Deadlines permet de rechercher des conférences, de les filtrer par domaine de recherche et de suivre les comptes à rebours. Les données d'échéances sont fournies avec l'application et peuvent être actualisées. La plupart des conférences relèvent de l'informatique, et quelques-unes de domaines comme les neurosciences et la physique.

## Figures, équations et tableaux

### Diagram Composer

Diagram Composer vous demande d'abord à quoi sert le diagramme : TikZ pour LaTeX, un diagramme fletcher pour Typst ou un organigramme Mermaid pour Markdown. Dessinez sur un canevas avec des rectangles, cercles, ellipses, losanges, textes, connecteurs, aimantation, couleurs de remplissage et de bordure, annuler, rétablir, mini-carte et canevas clair ou sombre. Le panneau de code et le dessin restent synchronisés dans les deux sens, et le code que le canevas ne sait pas dessiner est conservé tel quel. Les figures TikZ se compilent isolément, les diagrammes Typst se prévisualisent avec le Typst du projet et Mermaid utilise le moteur de rendu de l'application.

La source enregistrée conserve le modèle du diagramme pour une prochaine modification, et Diagram Composer importe les fichiers `.tikz`, `.tex`, `.typ`, `.mmd` et `.md`. Insérez le code à la position du curseur, ou enregistrez un PNG et la source dans le dossier `figures` du projet. La réparation IA facultative peut aider en cas d'erreur de compilation de la figure, et un modèle capable de vision peut examiner un rendu et affiner sa mise en page.

## Vérifiez le document avant qu'il ne quitte votre ordinateur

Preflight lit la source, la structure du projet, le journal du compilateur et le PDF actuel. Il regroupe les résultats par problème et indique l'origine de chaque résultat. Les vérifications peuvent s'exécuter ensemble ou séparément ; une entrée manquante est signalée comme indisponible ou partielle, et non comme une réussite. Les projets Typst ont leurs propres vérifications de la source pour les références et citations non résolues, le texte alternatif manquant, les métadonnées du document, les images manquantes, la confidentialité et l'évaluation anonyme. Les projets Markdown n'ont que les vérifications du journal de compilation et du PDF.

| Vérification | Ce qu'elle recherche |
| --- | --- |
| Compilation et mise en page | Compilations échouées, citations et références non résolues, avertissements de recompilation, glyphes manquants, boîtes trop pleines, texte tronqué, destinations PDF en double et formats de page mélangés |
| Préparation à la soumission | Classe du document, résumé, mots-clés, formats de figures, polices incorporées, version et restrictions du PDF, noms de fichiers portables, légendes et empaquetage propre des sources |
| Préparation ATS | Extraction du texte du CV, coordonnées, sections attendues, longueur du document et mises en page qui brouillent souvent les systèmes de suivi des candidatures |
| Accessibilité | Balises, texte alternatif, langue et titre du document, réglages du lecteur, structure des titres et tableaux, descriptions des liens, ordre de lecture, texte sélectionnable, signets et texte très petit |
| Références et ressources | Fichiers manquants, citations et renvois indéfinis, labels et DOI en double, champs bibliographiques incomplets, entrées non citées et figures manquantes |
| Confidentialité et évaluation anonyme | Identifiants, clés privées, fichiers sensibles, balisage de brouillon, commentaires internes, champs d'auteur, remerciements et métadonnées d'identité du PDF |

Les profils de publication couvrent la publication générale, arXiv, IEEE, ACM, les autres revues et les thèses. Vous devez tout de même consulter le guide actuel aux auteurs de la revue pour connaître ses marges exactes, limites de pages, règles de taille des fichiers et consignes de soumission.

Les vérifications d'accessibilité font référence à PDF/UA, Matterhorn et WCAG et signalent la partie de PDF/UA-1 vérifiable automatiquement. La préparation d'un export accessible peut ajouter des métadonnées LaTeX, des déclarations d'en-tête de tableau et des espaces réservés pour le texte alternatif lorsque la classe et les paquets actifs le permettent. Pour Typst, la préparation de l'export propose PDF/A et PDF/UA.

Preflight est un ensemble de vérifications automatiques, pas un certificat de conformité. Il ne peut pas juger si un texte alternatif est pertinent, si l'ordre de lecture est logique ou si le contraste est suffisant. Pour une déclaration formelle de conformité en matière d'accessibilité, validez le PDF final avec l'outil exigé par la revue.

Oleafly fonctionne avec un dépôt Git normal. ## L'IA est facultative

L'éditeur, le compilateur, l'aperçu PDF, les citations, la relecture et Preflight fonctionnent avec l'IA désactivée. Lorsqu'elle est activée, l'IA utilise les mêmes fichiers de projet et les mêmes outils que le reste de l'application.

### Demandez à un assistant au sujet du projet ouvert

Avec un fournisseur configuré, l'assistant peut :

- Lire un fichier du projet ou effectuer une recherche dans le projet avant de répondre.
- Expliquer une section, une équation, une citation ou une erreur de compilation.
- Réviser la prose, créer des fichiers, renommer des fichiers et effectuer des remplacements ciblés.
- Compiler le projet, lire le journal, extraire le texte du PDF et examiner les pages rendues lorsque le réglage de capture PDF est activé.

## Un terminal à côté de l'article

Ouvrez des onglets shell pour le projet actif sans quitter l'espace de travail. Jusqu'à dix sessions de terminal peuvent être ouvertes par projet. Renommez et colorez les onglets, fermez une ou plusieurs sessions et conservez leurs libellés avec le projet.

Utilisez un onglet pour exécuter un script, inspecter un jeu de données, vérifier un fichier généré ou utiliser un autre outil CLI. C'est votre shell, avec le même répertoire de projet à la disposition des commandes que vous choisissez d'exécuter. Les chemins de fichiers et les adresses web dans la sortie sont des liens. Cmd-cliquez sur l'un d'eux (Ctrl-clic sous Windows et Linux) pour ouvrir un fichier du projet à la ligne et à la colonne indiquées par la sortie, un PDF ou une image dans sa visionneuse, ou une adresse web dans le navigateur.

## Navigateur pour les tâches de computer use

Le navigateur intégré est en bêta et désactivé par défaut. Activez-le dans Paramètres > Expérimentation > Navigateur web. Il s'ouvre dans une fenêtre distincte du système d'exploitation avec des onglets, une barre d'adresse, des commandes de navigation et des webviews de contenu isolées. Il sert principalement de surface de computer use : un agent peut ouvrir une URL et attendre son chargement pendant que vous gardez le manuscrit dans la fenêtre principale.

L'outil computer use ne peut pas lire, capturer, cliquer sur le contenu d'une page ni l'exécuter sous forme de script. Les pages distantes n'ont pas accès à l'IPC d'Oleafly et la navigation externe suit la politique d'approbation active. Utilisez les outils de littérature lorsque vous avez besoin de métadonnées ou de citations interrogeables.

## Version actuelle

Oleafly est en bêta. La coédition en direct, les commentaires et la synchronisation en arrière-plan entre appareils ne sont pas disponibles dans cette version. Markdown n'offre pas encore de synchronisation entre la source et le PDF ni de vérifications Preflight de la source, et la synchronisation Typst nécessite Typst 0.13 ou une version plus récente. Vérifiez le moteur actif dans l'application et consultez le [journal des modifications](../../CHANGELOG.md) pour suivre les changements.
