\begin{abstract}
\noindent
Installing a package is supposed to copy files. In three of the largest
language ecosystems it also runs arbitrary code, because the package format
supports install-time hooks and the client executes them by default. We report
a 19-month measurement of that surface across three registries, covering
1.42~million package versions and 6.1~million recorded hook executions in an
instrumented sandbox. Hooks are not rare: 8.4 percent of versions declare one,
and the packages that do account for 31 percent of installs by download volume
because they cluster in build-tooling dependencies that everything else pulls
in. We built \tool, a sandboxed installer that records every syscall a hook
issues and classifies its behaviour, and we use it to separate legitimate
native compilation from behaviour that no build step needs. Of 119{,}400
distinct hooks, 2{,}214 contacted a network host that was not the registry,
408 read credential material outside the package directory, and 61 did both
while also obfuscating the payload. We disclosed 47 packages that we assess as
malicious and 190 that are merely reckless. Three quarters of the malicious
set were published within 72 hours of a maintainer account changing its
recovery email, which is a signal registries already hold and do not act on.
\end{abstract}
