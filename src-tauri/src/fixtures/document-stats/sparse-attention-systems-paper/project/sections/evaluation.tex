\section{Evaluation}
\label{sec:evaluation}

\subsection{Setup}

We evaluate on a single 24\,GB consumer accelerator paired with a 16-core host.
Models are three open-weight decoders at 3B, 8B, and 13B parameters, served in
bfloat16 with a paged key-value cache. Baselines are a dense tiled kernel in
the style of FlashAttention~\cite{dao2022flashattention}, a 2048-token sliding
window~\cite{beltagy2020longformer}, and the block-sparse pattern of
BigBird~\cite{zaheer2020bigbird}. Unless stated otherwise $B = 128$ and
$\varepsilon = 0.02$.

\subsection{Throughput and latency}

Table~\ref{tab:latency} reports median time to first token. \sysname{} is
faster than every baseline beyond 32k tokens, and it is the only configuration
that completes the 128k case on this device: both the dense kernel and BigBird
exhaust device memory during prefill.

\subsection{Quality}

Figure~\ref{fig:quality} plots perplexity against the retained-mass budget on a
held-out long-document corpus. Quality is flat until $\varepsilon$ exceeds
0.05, after which the sliding-window failure mode reappears: the model loses
distant coreference and perplexity climbs sharply.

\subsection{Where the approximation fails}

Two regimes degrade. Retrieval-style prompts, in which a single distant token
carries the answer, concentrate mass in one block and are handled well. The
harder case is a prompt with diffuse, nearly uniform attention: the probe's
bound is loose, the guard fires, and \sysname{} falls back to dense
computation for those heads with a 12 percent latency penalty relative to
running dense from the start. We report this rather than tuning it away
because it determines when the scheduler should not be enabled.
